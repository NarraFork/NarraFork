# 核心流程

主题节点按"一块功能是什么"组织；一个真实的改动常常横跨好几块。这里按**发生顺序**把最常被一起改动的几条路径串起来：每一步一行，写明谁做、哪个函数、该读哪个主题节点。改一个功能前先在这里找到它在哪条路径的哪一步，再顺着链接读主题节点，就能知道还有哪些步骤会被牵连。

流程节点只指路，不重复主题节点的细节；每条流程末尾的「改它时」写的是"典型改动会一起碰到哪几步"。

## 怎么用
- 想改"消息怎么进来、模型怎么被请求、输出怎么到界面"：先看 [一轮对话](turn.md)。
- 想加或改一个工具、权限判断、审批卡片：看 [一次工具调用](tool-call.md)。
- 想改写文件、改动展示、回退：看 [一次文件修改与回退](file-change.md)。
- 想改子代理、后台任务、嵌套限制：看 [一次子代理委派](subagent.md)。
- 想改压缩的触发、标记、压缩后读什么：看 [一次上下文压缩](compaction.md)。
- 这些路径互相嵌套：一轮对话里会有工具调用，工具调用里会有文件修改或子代理，一轮里随时可能触发压缩。

## 下面有什么

- [一轮对话](turn.md)：用户消息进入、排队、组装上下文、请求模型、流式输出、落库、广播到前端。
- [一次工具调用](tool-call.md)：模型发出工具调用、权限判断与审批、在哪执行、结果写回与广播。
- [一次文件修改与回退](file-change.md)：工具写文件、写队列与变更证据、在界面里看到改动、回退时怎么恢复。
- [一次子代理委派](subagent.md)：派出子代理、选模板与工具、嵌套与资源、结果怎么回到父会话。
- [一次上下文压缩](compaction.md)：什么时候触发、压缩消息怎么插入、之后的请求从哪开始读。
