# 协作

这一块解决"多人、多入口地围绕同一批会话工作"：

- 项目是归属单元：会话按工作目录/显式上下文归入项目，项目 ACL（owner / 可见性 / 授权）是进入项目的外层门，门内的会话与知识仍受各自 ACL 约束。
- 团队建在项目之上：一个协调者叙述者 + 子代理，工作项即分支加 worktree；团队没有自己的成员表，成员关系完全取自协调者的叙述者 ACL。
- 聊天房间（dm / narrator / bot）是与叙述者上下文隔离的对话存储；bot 房间是 bot 叙述者面向人的通道，公开分享的访客讨论也复用同一套房间。
- 通知与注意力把聊天、权限请求等事件投影成通知中心行和"需要人处理"的收件箱，并向钉钉/飞书 webhook 发外部提醒（收件人来源见最近标签页）。
- 分享把会话（令牌链接，访客只读 + 讨论）或文件（临时链接）开放给没有账号的人。
- IM 网关把 Telegram/Discord/Slack/飞书/微信/QQ/Webhook 的消息映射到叙述者；团队会话明确禁止从 IM 驱动。

共同点：大多只在 SQLite 后端可用（项目/团队的写路由在 PostgreSQL 上返回 503），读路径都有条数/字节/时间上限。

- [团队](teams/index.md)：协调者 + 子代理树、工作项、跨团队重叠与独占路径、协调者软限制与团队状态、团队页、多人使用。

- [分享](sharing.md)：公开会话分享、文件分享。
- [IM 网关](gateway.md)：Telegram/Discord/Slack/飞书/微信/QQ/Webhook 接入、会话映射、命令（钉钉不在网关里）。
