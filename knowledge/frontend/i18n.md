# 国际化

界面文案用 i18next + react-i18next，资源是 `frontend/locales/{en,zh-CN}/<命名空间>.json`，按命名空间懒加载，不随首屏一起下发。

## 关键规则
- 支持的语言定义在 `shared/i18n-locales.ts`：`SUPPORTED_LOCALES = ["en", "zh-CN"]`，默认与回退语言 `en`；`zh-CN` 的别名含 `zh`、`zh-Hans`、`zh-SG`，由 `normalizeLocale` 归一。
- 语言检测（`frontend/lib/i18n.ts:initI18n`）：顺序 `localStorage["narrafork_lang"]` → `navigator`，结果缓存回 localStorage；`load: "currentOnly"`，`useSuspense: true`。切换语言用 `changeAppLanguage`，会先加载当前路径所需命名空间再切换，并同步 `<html lang/dir>`。
- 命名空间清单是 `i18n.ts:namespaces`（21 个：common、errors、nav、settings、narrator、narrators、git、terminal、knowledge、outline、chat、plugins、remote…），`normalizeNamespace` 对清单外的名字直接抛错。
- 资源加载器在 `i18n-locale-loaders.ts`，把 Vite 专有的 `import.meta.glob` 隔离在这一个模块里；在 Bun 测试/类型检查下是空表，`loadLocaleResource` 会拒绝（所以测试里不渲染翻译文案）。
- 启动只阻塞 `common` + `errors`（`getInitialNamespaces`）。其余由 `I18nNamespaceGate`（`use(ensureI18nNamespaces(...))`，只挂起自己那一块）按需等；`getNamespacesForPath` 给出每条路径的命名空间集合：登录后路径一律包含 `APP_SHELL_NAMESPACES`（common、errors、nav、settings、narrator、narrators），公开路径（`/login`、`/oauth/authorize`、`/licenses`、分享页）也都含 `errors`，否则错误提示会静默退回服务端英文。
- 新增路由要在 `getRouteNamespaces` 里登记它用到的命名空间；`tests/frontend/app-shell-i18n-namespaces.test.ts` 断言每个登录后路径都含外壳命名空间。
- 加字符串时 en 与 zh-CN 必须同时加：`bun run i18n:check`（`server/scripts/check-i18n.ts:checkI18nResources`，CI 的 static-checks 里跑）检查两种语言命名空间/键结构兼容，并禁止不带 locale 参数的 `toLocaleString()` 等回退系统语言的格式化（`checkLocaleSensitiveFormatting`，`tests/frontend/i18n-resources.test.ts` 也跑）。

- 语言切换（`components/LanguageSwitcher.tsx`）：先 `changeAppLanguage(locale, getNamespacesForPath(当前路径))`，加载完才切换；`persistToAccount` 为真（默认）才把 `language` 写进用户偏好，登录页传 `false`，只靠检测器的本机缓存。

## 从哪读起
- `frontend/lib/i18n.ts`：初始化、路径→命名空间表、语言解析缓存。
- `frontend/lib/intl-format.ts`：带 locale 的数字/日期格式化入口。
- `frontend/lib/api-error.ts`：`describeApiError` 把 API 错误码翻成本地化文案。

## 改它时
- 加文案键：`frontend/locales/en/<ns>.json` 与 `zh-CN/<ns>.json` 同时加，`bun run i18n:check`（`server/scripts/check-i18n.ts`）检查两边命名空间与键结构，复数键按 `_one/_other` 等后缀归并；`tests/frontend/i18n-resources.test.ts` 在测试里也跑它。
- 加命名空间：把名字加进 `lib/i18n.ts:namespaces`、两种语言各建一个 JSON，并在 `getRouteNamespaces` 里登记用到它的路径（加载器由 `i18n-locale-loaders.ts` 的 `import.meta.glob` 自动收，不用再列）；漏登记则该命名空间不会被按路径预取。外壳用到的命名空间要进 `APP_SHELL_NAMESPACES`，`tests/frontend/app-shell-i18n-namespaces.test.ts` 会断言。
- 加支持语言：改 `shared/i18n-locales.ts`（`SUPPORTED_LOCALES`、别名、`LOCALE_OPTIONS`），服务端也读这份清单。
- 日期数字格式化必须带 locale（走 `lib/intl-format.ts`），否则 `checkLocaleSensitiveFormatting` 报错。
