# 模型供应体系重设计

> 状态：设计稿，待评审。依据 `main@434476d` 的代码现状。本文只定方向与契约，具体迁移、表结构以实施 PR 为准（schema 变更走 `server/db/schema.ts` → `bun run db:generate`）。

## 1. 目标

1. 常见场景零配置：新手只需登录订阅或粘贴一个 API Key 就能用，复杂选项默认隐藏。
2. 取消“模型聚合”功能，改为**默认聚合**：用户选的是模型，来源（渠道）放进二级菜单，支持“自动”和“指定”。自动模式按可排序的策略打分（价格、订阅重置时间等），并和纪元（代次）系统结合：纪元内保持缓存不切换，纪元轮替时重新选择。
3. 非管理员也能管理自己的模型来源（登录 Codex、填 Kimi Code / OpenCode Go 等套餐 Key）。个人来源默认隔离：**谁拥有叙述者就用谁的凭据**。共享叙述者、邀请协作不改变这一点。
4. 个人额度用完后，自动回落到管理员配置的团队共享来源。
5. 大幅简化模型目录，去掉让人困惑的配置项，消除报错和主线程阻塞。
6. 每个来源都能填写实际开销（订阅月费或真实单价），与理论价对比得出节省量。
7. 用户能分析自己各来源的用量。
8. 管理员能分析全体用户用量；用户可把自己的私人来源设为对管理员不可见。
9. 以 Codex 为标杆统一所有订阅制服务的体验，覆盖 OAuth 与 API Key 两类登录，并支持逐凭据的网络身份策略（代理、UA、设备 ID 等）。

## 2. 现状中需要改变的部分

| 现状 | 问题 |
|---|---|
| 模型值是 `前缀:模型`，前缀即供应商实例 | 同一模型在多个来源时是多个条目；聚合要另建“模型聚合”对象 |
| 所有供应商配置在全局 `settings.json`，凭据全局共享 | 无法按用户隔离；写设置时 `Atomics.wait` 最长阻塞主线程 2 秒 |
| `resolveProviderAndModel()` 只看模型前缀，不带用户上下文 | 无法按“谁付费”选凭据 |
| 回合的执行身份是**消息发送者**（`_currentUserId`） | 若直接拿来选凭据，协作者 B 会花掉自己的订阅，或者 A 的订阅被任何有写权限的人使用 |
| 只有 Codex 与插件写入 `credentialId` | NUG、自定义 API 的用量只能按前缀区分，无法按来源分析 |
| 只有参考价 `costUsd`，且按模型定价 | 没有实际开销，算不出节省量 |
| 用量分析全部 `requireAdmin`；`/api/dashboard/summary` 却把全员当日开销返回给任何用户 | 用户看不到自己；同时存在越权泄露 |
| 模型目录 8 层合并、变体/绑定/覆盖并存，4 个互相竞争的上下文窗口字段，每次编辑全量校验 242 个模型 | 配置难懂；全量校验约 50ms + 设置锁 + 整份 settings.json 重写 |
| Codex 凭据池能力最完整，但没有逐凭据代理/UA/设备 ID；Kimi、OpenCode 只有状态栏额度显示 | 订阅体验不一致 |
| 私密凭据以明文 0600 文件存放 | 加入个人凭据后需要至少应用层加密 |

## 3. 概念模型

用户可见的只有三个名词：**模型**、**来源**、**策略**。内部再细分为服务、凭据、渠道。

| 概念 | 含义 | 举例 |
|---|---|---|
| **服务 Service** | 一种上游服务，由**服务模板**描述协议、端点、登录方式、额度探测、模型列表 | Codex（ChatGPT 订阅）、Kimi Code、OpenCode Go、Anthropic API、DeepSeek API、NUG、TokenDance、某个自定义中转 |
| **凭据 Credential** | 服务下的一个账号或 Key。带归属、秘密、网络身份、计费、额度窗口、隐私设置 | “我的 ChatGPT Pro 账号”、“团队 DeepSeek Key” |
| **渠道 Channel**（UI 中叫“来源”） | 运行时可路由的单位 = 服务 × 凭据。记录健康度、缓存亲和、实际单价 | `Kimi Code · 我的 Key` |
| **模型 Model** | 逻辑模型，由目录统一身份，如 `claude-opus-4-6`。一个模型可由多个渠道提供 | 叙述者选的就是它 |
| **计费主体 Billing owner** | 决定这次请求能用谁的个人来源。**等于叙述者的所有者** | 见 §5 |
| **策略 Strategy** | 自动模式下候选渠道的排序规则 | 省钱 / 尽快用掉订阅 / 稳定 |

关系：

- 凭据归属于**用户**（个人来源）或**团队**（管理员配置的共享来源）。
- 一个服务模板可以有很多凭据；Codex 的“多账号凭据池”成为所有服务的通用能力。
- 渠道通过目录把各自的上游模型 ID 映射到逻辑模型。映射对用户透明，`anthropic/claude-opus-4.6`、`claude-opus-4-6-20260101` 都归入同一个模型。
- 插件供应商以“服务模板”的身份加入，凭据仍按用户或团队归属。

## 4. 路由：默认聚合 + 策略打分 + 纪元锁

### 4.1 叙述者保存什么

- `narrators.model`：逻辑模型 ID（不再带前缀）。
- `narrators.modelSource`：`auto`（默认）| `service:<id>` | `credential:<id>`。“指定”只缩小候选集，不绕过健康检查与权限。
- 渠道锁存在纪元记录里（已持久化在消息中），重启后不丢。

### 4.2 一次选择的步骤

```
resolveRoute({ model, source, billingOwner, narratorId, epoch, caps }) →
  { channel, adapter, upstreamModel, reason }
```

1. **候选**：提供该模型的全部渠道。
2. **过滤**：
   - 凭据可用于该计费主体：个人凭据只给其所有者，团队凭据按团队策略。
   - 渠道已启用、未归档、熔断未打开。
   - 已知额度未耗尽。
   - 能力满足本次请求，比如图片输入。
   - 符合用户的“指定”。
3. **分层**：个人来源 → 团队来源（默认；团队可配置为“团队优先”）。只有上一层没有可用渠道时才进入下一层。
4. **排序**：在同一层内按用户选择的策略**逐项比较**（字典序，便于解释“为什么选它”）。可选维度：

| 维度 | 定义 | 方向 |
|---|---|---|
| 边际成本 | 订阅窗口内额度 ≈ 0；额度外按 credits 价；按量计费按实际单价 × 预估本轮输入/输出；网关按其报价 | 低优先 |
| 重置紧迫度 | `剩余额度比例 ÷ 距重置时长`，越大表示越多额度即将过期作废 | 高优先 |
| 切换代价 | 非当前渠道且缓存仍热时，加上“整段上下文按未缓存价重算”的差额；纪元边界时为 0 | 低优先 |
| 稳定性 | 近期成功率、首 token 延迟 | 好者优先 |
| 用户手动优先级 | 凭据卡片上的排序 | 小者优先 |

预设：

| 预设 | 排序 |
|---|---|
| **省钱**（默认） | 边际成本 → 重置紧迫度 → 稳定性 |
| **用掉订阅** | 重置紧迫度 → 边际成本 |
| **稳定** | 稳定性 → 边际成本 |
| **均衡** | 同层轮询，会话亲和 |

用户可以在高级设置里拖动排序。

5. **纪元锁**：见 4.3。
6. **出站**：渠道的网络身份装配成 `ProviderTransport`（代理、UA、设备 ID、额外请求头），交给协议适配器。

`resolveRoute` 保持同步：读的是内存中按用户分组的渠道快照，凭据变更时通过事件总线失效重建，不在请求路径上查库。

### 4.3 与纪元结合

纪元（前缀纪元）只在**压缩成功**或**实际切换模型目标**时轮替（见 `docs/AGENT_PROVIDERS.md`）。在此基础上，渠道选择分三种时机：

| 时机 | 行为 |
|---|---|
| **纪元内** | 锁定当前渠道，不因打分变化而切换，保住上游缓存 |
| **纪元边界**（新会话、压缩成功、用户换模型） | 完整重新选择，切换代价为 0 |
| **缓存已冷**（距上次请求超过该渠道缓存 TTL，可关闭） | 允许在**同协议族**渠道间重选，不开新纪元；跨协议族等到下一个纪元边界 |
| **被迫切换**（额度耗尽、鉴权失败、熔断） | 立即排除当前渠道重选。若策略是“等待重置”且重置在 N 分钟内（沿用 `provider-quota-wait.ts`），则等待；跨协议族时按“实际切换模型目标”开新纪元 |

订阅额度刷新时，额度探测器发出 `credential.quotaRefreshed` 事件。锁在更贵渠道上的叙述者被标记为“有更优来源”，在下一个纪元边界或缓存冷点自动切回，不打断进行中的纪元。

典型过程：Codex 额度用完 → 被迫切到团队 DeepSeek Key（同时开新纪元）→ 若干轮后压缩 → 新纪元开始时 Codex 已重置 → 自动切回 Codex。

纪元目标指纹从 `前缀:模型` 改为 `协议族:逻辑模型`，同协议族内换凭据不再被误判为换模型。渠道锁单独记录在纪元记录中。

## 5. 归属与隔离

### 5.1 计费主体规则

**计费主体 = 叙述者的 `ownerUserId`**，与谁发的消息无关。

| 场景 | 计费主体 |
|---|---|
| 所有者自己发消息 | 所有者 |
| 协作者 B 在 A 的叙述者里发消息 | A（A 通过授予写权限表示同意；仓库与工作仍是 A 的） |
| 子代理、搜索子代理 | 沿 `aclRootNarratorId` 找到根叙述者的所有者 |
| 定时任务 | 任务创建的叙述者归 `task.createdBy`，即其所有者 |
| 标题、摘要、压缩、翻译 | 同叙述者所有者 |
| Bot 聊天房间、网关平台 | Bot 叙述者的所有者 |
| 所有者已删除（`ownerUserId` 为空） | 只能用团队来源 |

`senderUserId` 仍然记录在用量里，用于审计“谁触发了这次开销”。

### 5.2 防误用

- 个人凭据可选“**仅限本人发起**”。打开后，协作者发起的回合跳过这条凭据，直接回落团队来源或报错。
- 叙述者设为公开可写、加入 Bot 房间时，若会动用个人订阅，界面明确提示。
- 管理员把消费级订阅（如 ChatGPT Plus）加入团队来源时提示：这类套餐的用户协议通常不允许多人共用，团队来源建议只放 API Key 或企业套餐。

### 5.3 团队来源与回落

- 管理员配置团队来源，并设定**团队策略**：哪些用户或角色可用、可用哪些模型、每人每月预算（按参考价或实际价）。
- 个人层没有可用渠道时回落团队层（目标 4）。回落写入叙述者的状态条：“个人额度已用完，正在使用团队来源 · 约 2 小时后 Codex 重置”。
- 预算耗尽后按团队策略处理：拒绝，或仅允许指定的低价模型。

## 6. 凭据：以 Codex 为标杆的统一形态

每条凭据都有同样的五块内容，订阅类与 API Key 类共用一套界面。

| 块 | 内容 | 默认 |
|---|---|---|
| **登录** | OAuth（浏览器 / 设备码）、PAT、Agent Identity、API Key，由服务模板声明支持哪几种 | 模板首选方式 |
| **额度** | 模板提供额度探测器，统一产出 `windows[]: { kind: 5h / weekly / monthly / balance, usedRatio, resetsAt }` | 自动探测；不支持的服务显示“未知” |
| **网络身份** | 代理（跟随全局 / 直连 / 系统 / 自定义）、UA 模式、设备 ID（创建时随机生成并固定，如 Codex installation id）、额外请求头 | 全部跟随服务模板；高级选项中可改 |
| **计费** | 订阅：月费、币种、续费日；按量：参考价折扣或自定义单价；网关预付：采用上游报价（NUG `quotaCost`） | 未填写时只计参考价，不算节省 |
| **归属与隐私** | 个人 / 团队；“仅限本人发起”；“对管理员隐藏用量” | 个人、关闭、关闭 |

额度探测器先覆盖已有实现：Codex `/wham/usage`、Kimi `/coding/v1/usages`、OpenCode Go `/usage`、NUG 余额、TokenDance。其余 Token Plan（MiniMax、智谱、MiMo）按官方接口逐个补，拿不到时只靠 429 被动发现。

Codex 现有的能力（优先级、档位排序、会话亲和、连续失败停用、归档、配额预测）上移为**通用凭据池**，Codex 只保留 OAuth、PAT、Agent Identity 的登录实现与额度探测器。

## 7. 存储与安全

- 服务、凭据、团队策略迁出 `settings.json`，进 SQLite：
  - `provider_services`：id、归属、模板 ID、名称、协议、baseUrl、高级配置 JSON。
  - `provider_credentials`：id、serviceId、`ownerUserId`（空 = 团队）、标签、登录方式、密文、状态、优先级、归档时间、网络身份 JSON、计费 JSON、隐私标志。
  - `credential_quota`：最近一次额度快照，由后台探测器写。
- 秘密字段以 AES-GCM 加密，密钥放在 `~/.narrafork/secret.key`（0600）。这只防数据库文件被单独拷走：控制服务器的人仍然能读到一切。“对管理员隐藏”是产品层面的承诺，不是密码学保证，界面要如实说明。
- API 只把凭据的公开投影交给前端，并且只给其所有者。管理员能看到团队凭据，看不到个人凭据的秘密。
- 读写都是带索引的单行 CRUD，变更后通过事件总线让路由快照失效，满足主线程规则。

## 8. 模型目录：缩到必要的最小集

### 8.1 运行时真正读取的字段

上下文窗口、最大输出、输入模态、推理档位 / 默认档 / 能否关闭、原生搜索、`tool_loading_modes`、四项参考价（输入 / 输出 / 缓存读 / 缓存写）。其余字段只用于展示。

### 8.2 新结构

只合并三层：

```
内置目录（随版本发布） < 上游发现（NUG / Gemini 列表等） < 用户覆盖（按逻辑模型，可选按渠道）
```

具体变化：

- **删除**：变体、绑定、overrides 数组、hidden ids、`legacyFields` 与永久保存的 `legacyArchive`、在线更新的固定 / 回滚 / 历史快照、长上下文计价编辑器、逐字段“未知”状态。
- **字段收敛**：上下文窗口只保留一个字段（替代 `working_context_tokens` / `max_input_tokens` / `context_window` / `legacy_context_window` / 供应商级 `defaultContextWindow` 五处），最大输出一个字段。
- **匹配**：去掉 `vendor/` 前缀、日期后缀、点号与短横的差异；同级多个候选时按确定顺序取一个并记 WARN，**不再在请求时抛错**。
- **校验**：只校验被编辑的那一条；违反约束时给出字段级中文提示（“最大输出 128K 超过了上下文窗口 64K”），而不是 `Invalid: max_output_tokens`。
- **存储**：用户覆盖存到独立表 `model_overrides`，不再改写 `settings.json`，不再触发设置锁和全量设置监听。
- **更新**：目录随发布更新。若保留在线更新，只保留“检查 / 应用”一个动作，下载、解压、校验放 worker。

### 8.3 界面

- 模型卡默认只读，每个字段标注来源（目录 / 上游 / 手填）。
- 只有“高级 → 修正模型参数”里能改上述 8 类字段。
- 新模型未匹配到目录时，用上游发现的值；仍缺上下文窗口时用保守默认值并在模型旁显示“参数未知”，而不是要求用户先填表。

## 9. 实际开销与用量分析

### 9.1 记录

`api_requests` 补充：

| 字段 | 含义 |
|---|---|
| `channelId`、`serviceId` | 所有渠道都必须写，不再只有 Codex |
| `billingUserId` | 计费主体，与已有 `userId`（发送者）并存 |
| `actualCostUsd`、`actualCostStatus` | 按量与网关来源逐条计；订阅类不逐条分摊 |

新增日汇总表 `usage_daily`，键为（日期，计费用户，渠道，逻辑模型，种类），保存 token、请求数、参考开销、实际开销（按量）。在 `finishApiRequest` 里和现有汇总同一事务做一次带索引的 upsert。叙述者删除后明细会级联删除，日汇总不受影响。

### 9.2 节省量

- **按量 / 网关**：节省 = Σ 参考开销 − Σ 实际开销。
- **订阅**：周期节省 = 该凭据本周期 Σ 参考开销 − 月费按周期折算。同时显示“利用率”：已用参考价值 ÷ 月费。
- 所有计算基于 `usage_daily`，在只读 worker 上执行。

### 9.3 谁能看什么

| 视图 | 内容 |
|---|---|
| **我的用量**（所有用户） | 按来源 / 模型 / 日期分析；实际开销 vs 参考开销；各订阅利用率与节省 |
| **团队用量**（管理员） | 全体用户、全部团队来源；按用户 / 来源 / 模型拆分；团队预算执行情况 |
| **隐私** | 标记“对管理员隐藏”的个人来源，其用量不进入管理员的明细与拆分；管理员总览只显示一行“N 位用户有未披露的私人用量”，不含数字 |
| **修复** | `/api/dashboard/summary` 改为只统计当前用户（管理员另有团队总览） |

## 10. 交互设计

### 10.1 首次使用

设置向导与“添加来源”共用一张页面，第一屏只有几张卡片：

- **登录 ChatGPT**（Codex）
- **Kimi Code / OpenCode Go / MiniMax / 智谱 / MiMo 套餐**：粘贴 Key
- **API Key**：Anthropic、OpenAI、DeepSeek、Gemini……
- **其他**：自定义中转、NUG、插件（进入高级流程）

粘贴 Key 后自动完成：识别服务、探测协议、拉模型列表、读额度。成功即回到对话，模型选择器里已经出现可用模型。

### 10.2 模型选择器

- 一级：逻辑模型，按厂商分组。每项带来源标记（个人订阅 / 个人 Key / 团队），不可用的置灰并说明原因。
- 二级“来源”：
  - **自动**（默认），显示当前选中的来源和理由，如“Codex · 主账号，订阅额度内，边际成本 0”。
  - 可用来源列表：额度条、重置倒计时、实际单价。
  - 点任一来源即“指定”。

### 10.3 设置页结构

| 位置 | 内容 |
|---|---|
| 设置 → **我的来源** | 按服务分组的凭据卡片；Codex 式详情页（额度窗口、网络身份、计费、隐私） |
| 设置 → **路由策略** | 预设、排序拖动、纪元锁选项、额度耗尽时“等待重置 N 分钟内 / 回落团队” |
| 设置 → **我的用量** | §9.3 |
| 管理 → **团队来源** | 团队凭据、团队策略（可用人群、模型、预算） |
| 管理 → **团队用量** | §9.3 |
| 高级 → **模型参数** | §8.3 |

高级选项（协议、baseUrl、额外请求头、UA、代理、设备 ID、目录覆盖）一律折叠在“高级”里，模板默认值能用就不展示。

## 11. 迁移

| 现有 | 迁移为 |
|---|---|
| `customApiProviders` / `openaiProviders` / `anthropicProviders` / `geminiProviders` / `nugProviders` / `tokendance` / `commandCode` | 团队服务 + 团队凭据 |
| `codex-credentials.json` | Codex 服务下的团队凭据（保留优先级、归档、用量历史） |
| `narrators.model = 前缀:模型` | 逻辑模型 + `modelSource = service:<原前缀对应服务>`，行为不变；用户可一键改为“自动” |
| 模型聚合 `__agg__:id` | 逻辑模型 + `auto`；priority 聚合的成员顺序转为这些凭据的手动优先级 |
| `summaryModel`、子代理模型池、搜索渠道模型 | 逻辑模型（+ 可选来源） |
| 目录本地层 `connections` / `overrides` | 仅保留 8 类运行时字段，转入 `model_overrides`；其余丢弃并记日志 |

迁移在后台分页执行，单批次有上限并让出事件循环，不在一个同步事务里改写上万行。

## 12. 分阶段实施

每个阶段都能独立发布，不依赖后续阶段。

| 阶段 | 内容 | 用户可见变化 |
|---|---|---|
| **P0 地基** | 所有渠道写 `channelId`；`usage_daily`；修复首页汇总越权；目录只校验被编辑项、覆盖迁出 `settings.json` | 设置不再卡顿；用量可按来源区分 |
| **P1 存储** | 服务 / 凭据入库并加密；通用凭据池（从 CodexManager 上移）；逐凭据网络身份 | Kimi / OpenCode 等获得 Codex 式详情页 |
| **P2 路由** | 逻辑模型、默认聚合、`resolveRoute`、策略预设、纪元锁、模型选择器二级菜单；迁移旧模型值与聚合 | “模型聚合”消失，来源变为二级菜单 |
| **P3 个人来源** | 个人凭据、计费主体规则、团队回落与团队策略 | 非管理员可登录自己的订阅 |
| **P4 开销与分析** | 计费配置、实际开销、节省量、我的用量 / 团队用量、隐私 | 用量页对所有人开放 |
| **P5 目录收尾** | 字段收敛、删除变体 / 绑定 / 遗留归档、新模型卡界面 | 模型参数页只剩必要字段 |

## 13. 待决问题

1. **协作者回合是否允许动用所有者个人订阅**：本文默认允许（与“请人坐到身边一起操作”一致），并提供“仅限本人发起”开关。若希望默认更严，可把开关默认值改为打开。
2. **“对管理员隐藏”的范围**：本文默认隐藏明细与数字，只显示“有未披露用量”。如果团队需要管理员掌握总量（例如核算服务器负载），可改为只隐藏来源名称与拆分。
3. **在线目录更新是否保留**：本文倾向随版本发布；若需要快速跟进新模型，只保留单一“检查 / 应用”。
4. **团队优先还是个人优先**：默认个人优先（省团队钱）。公司统一付费的部署可能希望团队优先，作为团队策略选项提供。
5. **跨协议族的缓存冷点切换**：本文限制为等到纪元边界。若实测收益大，可以把“缓存已冷”也视为合法纪元边界。
