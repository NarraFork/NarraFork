# 异步 AskUserQuestion：上下文、回答与处理闭环

状态：待人工审查。本文描述完整设计；实现代码保持原状。

## 1. 用户体验与系统职责

异步提问是持续存在的待决事项。Agent 发出问题后继续工作，用户选择合适的时间回答，Agent 在接收答案后结合当前任务给出处理说明。

完整流程：

```text
创建问题 → 等待用户回答 → 保存并投递回答 → Agent 判断当前适用性 → 确认处理结果
                 ↓                                      ↓
             撤回／跳过                              澄清／补充／纠正
```

系统承担四项职责：

1. 向用户展示问题状态、等待紧迫程度和回答后的处理结果。
2. 向 Agent 提供带历史背景的自足回答回执。
3. 在聊天压缩后维持未决问题的可发现性与可读取性。
4. 协调回答投递、Await、会话继续和失败恢复。

答案的适用性由 Agent 根据当前工作判断，任务执行结果通过正常对话报告。问题记录、回答事件与处理确认分别提供这三个过程的可追溯依据。

## 3. 问题记录与创建协议

### 3.1 提问背景

异步请求增加事项级 context，描述与回答有关的任务背景及等待期间的行动。

示例：

> 正在对拖拽宽度冻结做只读预览采样。浏览器停在登录页；等待期间先继续静态调查。此答案用于恢复实际采样。

新版 async=true 要求 context 非空。特殊有效条件可以写在这段背景中。问题正文与 context 合起来应足以让 Agent 在脱离原聊天后理解这个决策。

同步提问沿用现有输入协议。旧记录的缺失背景标记为「提问背景未知」，Agent 结合已有问题和当前任务判断，必要时澄清。

### 3.2 持久化结构

在现有问题记录上增加 context 和 resolution：

```text
QuestionRecord
  id                         现有问题记录 ID
  narratorId                 发起执行主体
  toolCallId / toolUseId      原工具关联
  questions[]                含稳定题目 ID 的原问题与选项
  context                    提问时的背景
  status                     open / answered / dismissed / withdrawn
  answers / annotations      首次提交的答案与备注
  answerMessageId            当前回答事件引用
  resolution                 可空的处理确认
  executionPrincipal         创建时的执行身份
  decidedBy / decidedAt      用户决定的归属与时间
  createdAt                  创建时间
```

题目、选项、context 和原工具关联在创建时冻结，构成问题快照。问题修正通过撤回原事项、重新提问完成，旧记录保留原始含义。

回答及补充通过消息关联表按 questionId、createdAt、messageId 索引，关联项保存事件类型与该事件的处理确认。正文保存在消息历史中。这份关联支持补充分页，以及历史回退时恢复上一个回答与其处理状态。

题目 ID 用于答案关联，标题用于展示。选项按冻结的位置及原始内容解释。一次事项支持现有最多四题，context 描述共享背景，各题 description 补充自己的决策细节。

SDK 中的原提问及工具输入保持创建时的内容，回答归入独立问题记录与用户事件。这使 Fork 共享的原历史保持其分叉时的语义，后续回答沿原执行主体的新消息流展示。

旧 header 键由服务端映射到题目 ID；映射存在歧义时返回明确错误，客户端保留草稿供修正。

### 3.3 处理确认

```text
resolution = null | {
  answerMessageId,
  note,
  resolvedAt,
  actor
}
```

resolution 为 null 表示当前答案待回应；非空表示 Agent 已判断并说明处理结果。note 可以解释采用、当前已无需使用、需要澄清或多题的混合处理。

界面使用「已回答，待回应」和「Agent 已回应」。该确认对应 Agent 的处理说明；相关任务是否执行成功由任务结果报告表达。

## 4. Agent 接口与状态流转

### 4.1 工具职责

| 工具／操作 | 输入 | 结果 |
| --- | --- | --- |
| AskUserQuestion | questions、context、async | 创建问题，返回问题 ID |
| Await(type=question) | 问题 ID、超时 | 等待用户决定，返回状态和回答事件引用 |
| Question.get | id | 问题快照、完整 preview、答案、补充事件及处理说明 |
| Question.list | cursor、filter | 当前执行主体的问题摘要与下一页游标 |
| Question.resolve | id、answerMessageId、note | 确认当前答案的处理结果 |
| Question.withdraw | ids、reason | 撤回开放问题 |

AskUserQuestion.withdraw 保留为兼容入口。Question 负责已创建事项的查询和管理，AskUserQuestion 负责提问，Await 负责等待。

Question.get 中的补充事件按消息顺序提供，有界分页返回，并携带下一页游标；Agent 据此理解答案及后续更正。

### 4.2 状态流转

| 事件 | 状态变化 | 对外表现 |
| --- | --- | --- |
| 创建 | → open | 待回答 |
| 用户提交 | open → answered，resolution=null | 已回答，待回应 |
| Agent 确认 | answered，写入 resolution | Agent 已回应，显示 note |
| 用户跳过 | open → dismissed | 用户已跳过 |
| Agent 撤回 | open → withdrawn | 已撤回，显示原因 |
| 用户补充／纠正 | answered，更新 answerMessageId，resolution=null | 新补充待回应 |

answered 事项通过处理确认说明答案如何使用；withdraw 用于结束仍开放的提问。

resolve 匹配当前 answerMessageId，采用短事务或 CAS 更新。重复相同确认返回既有结果；旧回答版本的确认返回冲突及最新事件引用，Agent 读取补充后重新判断。

### 4.3 澄清与补充

需要澄清时，Agent 写入当前处理说明并正常询问，或创建一个自足的新问题。

卡片的「补充／纠正」入口打开普通消息编辑器并附上结构化问题引用。提交后保存为新的用户事件，原答案和旧处理说明保留在消息历史中，问题重新进入待回应。

用户补充事件采用与首次回答相同的权限、投递和调度规则。处理确认与回答事件引用绑定，使并发更新具备明确的先后关系。

## 5. 回答回执与模型语义

### 5.1 回执组成

从问题快照与用户回答生成自足回执：

1. 问题 ID、提问时间。
2. 标为「提问时背景」的 context。
3. 每题原问题与全部选项的标题、描述。
4. 对应题目的实际选择、自定义答案和备注。
5. 当前回答事件引用，以及结合当前任务判断并确认处理的提示。

preview 通过详情按需读取，回执携带省略提示。选项含义直接进入回执，支持「除了第二项都可以」这类依赖多个选项的自由回答。

回答表达用户的真实意图，协议来源沿用 user。Agent 根据当前任务及用户答案决定行动。用户在答案中提出的新要求，也按照正常用户请求理解和处理。

历史背景和新答案分区编码，平台生成事件元数据，用户文本安全转义。执行权限继续由原有授权机制判定。

### 5.2 模型与 UI 投影

一份回答事件生成两个投影：

- 模型文本：完整的自足回执。
- UI body：问题关联、题目标题、答案与事件引用，用于简短展示和展开详情。

示例模型文本：

```text
用户回答了历史问题 Q17。
提问时间：……
回答事件：……

提问时的背景（请结合当前状态判断）：
正在做只读预览采样；浏览器停在登录页；等待期间继续静态调查。
答案用于恢复实际采样。

原问题：采样预览如何登录？
当时选项：
1. 正常登录：用户在预览中完成登录。
2. 临时测试账号：凭据仅供本次只读采样，按会话敏感数据处理。

用户回答：使用临时测试账号。
用户补充：……

请结合当前任务判断如何使用答案，并确认处理结果。
需要澄清时，请说明缺少的信息。
```

## 6. 压缩后的恢复与持续可见性

### 6.1 回答到达时

问题记录独立于聊天压缩保留。回答到达后直接从该记录生成回执，模型因此获得完整语义背景。

UI 从问题记录打开详情；原消息定位用于追溯。已压缩的聊天和仍可读取的问题快照各自承担历史与业务详情职责。

继承到 Fork 的回答事件、已删除原事项的事件，以及原事项当前无法读取的事件，使用该消息保存的结构化 body 展示只读历史快照。快照体现事件当时的背景、选项与回答；当前事项的查询和操作遵循原执行主体权限。

### 6.2 未决问题提示

每个 loop pass 的上下文准备阶段，从问题表生成有界提示：

| 状态 | 提示内容 |
| --- | --- |
| open | ID、标题、awaited |
| answered 且当前 resolution 为空 | ID、标题、当前事件引用、Question.get 读取入口 |

回答本身后来被压缩时，Agent 仍能通过提示找回问题、答案和补充。已回应、跳过、撤回的事项归入历史查询。

提示保留摘要与引用，正文通过详情读取。超出预算时显示剩余数量和 Question.list 分页入口。多 turn 的同一 pass 通过下一 turn 供给机制接收新回答和状态变化。

提示在会话运行时提供上下文；后台调度由回答事件与现有会话恢复机制驱动。

### 6.3 历史生命周期

- 有效性：Agent 根据当前任务与提问背景判断，时间与压缩边界作为参考信息。
- 归档：问题详情继续可读，回答保存后等待会话恢复执行。
- 删除／回退：按历史边界同步取消提问或恢复答案和处理状态；删除范围内的事项从活动提示移除。
- Fork：继承历史中的问题和回答作为背景，活动事项及处理权限归原执行主体。新会话需要询问时创建自己的事项。
- 会话删除：问题记录遵循会话数据的删除策略。

## 7. 投递、等待与会话继续

### 7.1 调度规则

| 执行状态 | 回答处理方式 |
| --- | --- |
| 正在生成或执行工具 | 保存回执，通过 onNextTurn 类接缝在下一个安全模型 turn 供给，当前生成和工具执行正常结束 |
| 正在 Await 对应问题 | 建立回执可见性后解除等待，下一模型请求包含答案 |
| 正常空闲且允许自动继续 | wakeIfIdle 启动回答处理轮次，Agent 判断当前行动 |
| 用户停止、冻结、归档或权限待恢复 | 保存回答，界面显示「恢复会话后处理」 |
| 子代理 | 沿原执行身份，通过 resumeSubagent 继续处理，结果走现有父子代理通道 |

安全模型 turn 位于完整工具结果组之后。运行中的内存历史接收回答事件，后续 pass 从持久化消息加载；这两个读取路径对同一模型请求提供一份回执。

会话保存明确的停止原因，调度器据此区分正常空闲和用户主动停止。

### 7.2 提交与恢复契约

1. 用户提交通过现有决定状态更新获得唯一决定权，重试返回既有结果。
2. 回答内容、回答消息与 answerMessageId 通过短事务或补偿形成可恢复关联。
3. API 根据实际结果返回已保存、可处理或具体失败信息；前端据此显示提交结果并保留失败草稿。
4. 回答提交后解除 Await。可靠入队时，Await 返回决定状态与回执引用；队列暂满或调度延期时，Await 从当前事件读取有界全文，作为下一模型请求的工具结果。供给恢复后，历史投影根据事件 ID 保留一份完整回执。
5. 回答到达与 loop 退出由现有会话串行化接缝协调；最终生成阶段的新答案也进入处理安排。
6. 同一会话的多个回答合并继续请求，依次处理；调度错误采用现有有界恢复策略。
7. 重启后通过持久化待回应记录恢复可发现性，允许恢复执行的会话继续处理，主动停止的会话等待用户恢复。
8. 用户跳过时，Await 返回 dismissed；Agent 根据该决定判断下一步。其余场景在下一轮读取状态变化。

传输与调度错误通过现有运行状态及错误信息展示，并提供对应重试入口。问题业务状态持续表示用户决定和 Agent 回应。

## 8. 人类交互

### 8.1 原问题卡片

```text
AskUserQuestion · 已提交            待回答
恢复采样预览登录
背景：只读采样停在登录页，静态调查继续
[选项 / 自定义回答]
[提交回答] [跳过]
```

工具执行标签表达提交结果，事项标签表达问题进度。Await 显示「Agent 正在等待」；其他开放事项显示「可稍后回答」。

提交后卡片折叠为标题、可展开答案和「待回应／Agent 已回应」。处理说明展示在卡片内。跳过与撤回使用终态卡片展示决定及原因。

### 8.2 时间线回答事件

回答事件默认显示「你回答了『恢复采样预览登录』」。展开后显示答案、问题详情、原卡片定位和「补充／纠正」入口。

专门的回答组件表达真实回答者及事件归属。模型回执与人类展示分别按各自阅读需求组织内容。

### 8.3 收件箱

| 分组 | 内容 |
| --- | --- |
| 待我回答 | open，Await 事项优先 |
| 待 Agent 回应 | answered 且当前 resolution 为空 |
| 历史 | 已回应、跳过、撤回 |

收件箱与原卡片共享状态、权限和草稿。用户行动通知针对待回答事项；待 Agent 回应分组提供提交后的进度查看。

### 8.4 敏感回答

自由答案按会话敏感数据保护，默认折叠。通知、列表和未决提示使用标题与状态摘要；正文通过有权限的详情读取。Agent 的处理说明以行动结论为主，凭据留在原回答中。

## 9. 大小预算、查询与权限

下列数值为设计预算；实施时与既有限制统一为共享常量：

| 项目 | 预算 |
| --- | --- |
| context | 2 KiB UTF-8 |
| 问题快照（题目、选项、preview、context） | 64 KiB |
| 单次答案与备注 | 16 KiB |
| 处理说明 | 2 KiB |
| 默认模型回执（含模板开销） | 80 KiB |
| 未决提示 | 最多 16 项，4 KiB |
| 列表与补充事件分页 | 单页最多 32 项 |

入口校验快照、答案以及可生成回执的聚合大小。超限返回具体错误，表单保留草稿供编辑。详情包含有界 preview；旧超大记录提供有界摘要、读取说明与受控历史读取路径。

列表查询按会话与状态索引分页，只选择摘要字段。补充事件按关联消息游标读取。WS 推送问题 ID 和状态变化，详情由客户端按需获取。

get/list 遵循原会话读取权限，resolve/withdraw 校验执行主体和事项归属。记录分别保留真实回答者和原执行身份。

操作沿用现有超时、取消和慢操作日志。日志记录 ID、状态、大小、耗时与错误类别，敏感正文通过会话详情管理。

## 10. 实现职责与兼容路径

1. 扩展现有 question schema，增加 context 和当前回答的处理确认，按 schema → db:generate 生成迁移。
2. 扩展异步提问输入、题目 ID 提交和服务端旧 header 键映射；歧义返回错误。
3. 扩展 asyncQuestionAnswers 结构化事件，从问题记录生成模型文本和 UI body。
4. 接入 Question 生命周期工具和 pass 级未决提示。
5. 实现回答事件关联的补充入口、处理确认和并发校验。
6. 打通原卡片、时间线、详情与收件箱，补齐中英文文案。
7. 验证运行中供给、Await 可见性、退出协调、停止原因与重启恢复。
8. 接入历史删除、回退、fork 和会话删除的事项生命周期。

旧记录继续支持读取和回答，缺失 context 显示背景未知。旧消息保留原存储格式，已有结构化来源的使用新回答组件，其余按原格式展示。

| 提问后继续工作 | 卡片显示待回答，工具显示已提交 |
| Await 等待 | 原卡片与收件箱准确显示等待紧迫程度 |
| 提问已压缩后收到答案 | 模型请求含自足回执，UI 可打开快照 |
| 回答又被压缩 | 未决提示可定位问题，详情可恢复答案与补充 |
