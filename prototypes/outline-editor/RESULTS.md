| 项 | 结果 | 关键数字 / 现象 |

| 1 中文输入法 | **通过**（38 条检查） | 组合中拼音不广播；组合中按 Enter / Backspace / 方向键（keyCode 229）不拆块、不合并、不跳块；组合期间对方改同一块：推迟应用、块 DOM 不被替换，提交后三方一致、光标在提交文字之后。测出并修了 2 个丢字 / 错位的 bug |

| 9 往返不丢 | **通过**（`bun test`，69 个测试） | 42 种方言内写法逐字不变；方言外写法拆成子块或原样保留；模糊测试 14,000 个随机块体：不动点 100%、文字不丢 100%、标记只降级不多出。发现中文标点与粗体的根本冲突（见「对设计的影响」3） |

## 做了什么

按 §6.2–§6.7 搭了一个完整的回路，全在一个页面里：

- **服务端**（`src/server/`）：块存储是真相；按页一个 Y.Doc，每个被编辑的块一个 Y.Text（存 markdown 源文本）。已有块的 Y.Text 在第一次被编辑（光标进入时发 `open`）时由服务端用 `content` 初始化；新建块由创建方在同一个事务里初始化。大纲事务（结构操作 + 正文的 Y 更新）作为一条消息到达，服务端按到达顺序原子处理：校验（同页、成环、父块存在）、同级排序键冲突时重新生成、删除时连带对方并发加进来的子块，写成提交，再把规范化后的操作和 Y 更新广播给这一页的参与者。agent：`agentRead` 返回快照并按会话缓存读到的正文；`agentWrite` 对正文以读取时的文本为基线三方合并（重叠就拒绝并返回当前内容），结构操作按读取时的版本检查，方言外的结构拆成子块并在返回里说明；页处于实时会话时合并结果作为一个参与者写进 Y.Doc。
- **网络**（`src/net.ts`）：每个客户端一条有序链路，消息结构化克隆，可设延迟、可暂停（用来制造「两人都在看到对方修改之前各自改」）。
- **客户端**（`src/client/client.ts`）：confirmed（服务端已确认）+ pending（已乐观应用、待确认）= visible；被拒绝时丢弃这一页的本地状态重新同步。按页 Y.Doc 副本；统一撤销栈：一个大纲事务一步（同一块里 1 秒内的连续输入合并），正文用每页一个 Y.UndoManager（只跟踪本地来源），结构用逆操作。
- **编辑视图**（`src/client/view.ts`）：一个编辑面一个 ProseMirror 视图（页、嵌入的子树、拼接视图）。
  - 投影：按块建节点，正文按源文本缓存解析结果；未变的块节点按身份复用；`findDiffStart / findDiffEnd` 只替换变了的范围。
  - 输入 → 大纲事务：单个块体内的 ReplaceStep 走快路径（只序列化这个块）；其余走全量 reconcile：比较前后两棵块树，得出 insert / move / delete / task，同级顺序用最长递增子序列求最少移动，再加上正文差异。
  - 远端修改：重新解析受影响的块，选区按「块 id + 源码偏移」保存，源码偏移经 Y.Text 的 delta 映射，再转回编辑器位置。
  - 输入法：组合期间组合中的块（连同子树）冻结；组合中不往 Y.Text 写（拼音不外发）；组合结束后把「shadow → 本地」的差异按期间的远端 delta 映射到当前文本上写，再按映射放回光标。
  - 外框：块节点的 node view 是原生 DOM（项目符号 / 折叠、复选框、在场标记），没有 React。
  - 嵌入：`![[…]]` 块体的 node view 里放一个子编辑视图（选区不跨边界）；客户端同时加入目标页的实时会话。
  - 剪贴板：复制时把选区序列化成 markdown 大纲（块内选区是行内 markdown）；粘贴时用方言把 markdown 拆成块树插入。
- **方言**（`src/dialect/`，不依赖 DOM 和 ProseMirror）：marked@18 分词 + `[[…]]` / `![[…]]` 扩展；解析同时产出「内容偏移 → 源码偏移」映射；序列化最小转义；写完读回核对、必要时降级（`safe.ts`）。

## 逐项结果

### 1 中文输入法 —— 通过

| 场景 | 结果 |
|---|---|
| 1a 块中间组合「ni → nihao → 你好」 | 组合中编辑器显示拼音，Y.Text、服务端、Bob 都没有拼音；提交后三方一致，光标在「你好」之后 |
| 1b 组合中按 Enter（229，输入法上屏字母） | 不拆块，字母在光标处；组合结束后真 Enter 在光标处拆块 |
| 1c 块首组合中按 Backspace ×2（229） | 只删拼音，不合并到上一块，上一块不变 |
| 1d 组合中 ↓ ↓ ↑ ←（229，选候选） | 提交在原位置，光标仍在原块 |
| 1e 组合期间 Bob 在同一块光标前、后各插一段 | Alice 编辑器里组合块保持本地内容、块 DOM 节点没被替换，而 Alice 的 Y.Text 已含 Bob 的修改；提交后 Alice / 服务端 / Bob 都是「【前】啊最后信息一块【后】」，光标在「信息」后，继续打字落在光标处 |
| 1f 组合期间 Bob 改另一个块 | 立即显示，组合不中断 |
| 1g 组合期间 agent 三方合并写同一块 | 被接受；组合块不重绘；提交后三方一致 |
| 1h 组合期间 Bob 把这个块往下移 | 组合不中断；提交后块在新位置、文字完整，光标还在这个块 |
| 1j 组合期间对方光标进入同一块 | 块外框的在场标记出现；块内的对方光标装饰在组合期间不画（ProseMirror 不在组合节点里画装饰），提交后出现；组合不受影响 |
| 1i（记录行为）组合中直接发 keyCode 13 的 Enter | 浏览器走 `beforeinput: insertParagraph`，ProseMirror 当成回车，块被拆开（12 → 13 块），而 `composing` 仍为 true。真实桌面输入法发 229 不会这样；安卓键盘的 Enter 走的正是这类路径，要真机测 |

测出并修掉的问题：

1. **组合结束后丢了对方的修改。** 组合结束后的第一笔本地事务拿「编辑器序列化结果」和「当前 Y.Text」做 diff，而 Y.Text 里有推迟期间收到的远端修改，于是被覆盖（Bob 的【前】【后】消失）。改为：和编辑器上次反映的源码（shadow）做 diff，再按期间的远端 delta 映射到当前文本上写（`view.ts` 的 `rebase` / `bodyChange`）。
2. **组合文字被放到块首。** 服务端第一次建 Y.Text 时的 map 事件把这个块的映射标成「重置」，内容没变所以没被清掉，之后精确的 delta 映射一直失效，退化成前后缀 diff，位置算错。改为：内容没变的块清掉残留映射。

### 2 移动端软键盘 —— 未测

这里没有 iOS / Android 设备和 Safari。没有做「连续 Enter / Backspace 时软键盘不收起、不闪烁」的任何验证。1i 的现象说明安卓上 Enter 的路径和桌面不同，P1 必须真机测。

### 3 跨块剪贴 —— 通过

- 3a 从 P1b2 的第 3 个字选到 P1b3 的第 3 个字，Ctrl+C，剪贴板逐字是：
  ```
  - 是真相，编辑器文档只是投影。参见 [[P2/P2b1|任务一]]
    - 每个块节点带块 id
    - **粗体**、*斜体*、`代码`、~~删除~~ 和 [链接](https://example.com)
  - 第三块
  ```
- 3b 块内选区复制出来是行内 markdown（`**粗体**、*斜体*、`），不带 `- `。
- 3c 同一选区 Ctrl+X：两端合并成一块（「块模型：拼接视图里也会出现」），中间两个子块删除，Bob 一致。
- 3d 再 Ctrl+V 到另一块末尾：拆成 4 个块、层级不变（新 id），光标在最后一个粘贴块末尾。
- 3e 外部 18 行 markdown（二级标题、任务两种状态、嵌套、列表项里的第二段、代码围栏、表格、结尾段落）粘贴到空块：拆成 9 个块（标题、两个任务、子项、普通项、拆出来作为子块的第二段、代码、表格、结尾段落），层级和任务状态正确，Bob 一致。
- 3f 单行 markdown 粘贴到块中间：留在块里，标记和提及被解析。
- 3g 多行粘贴到块中间：当前块在光标处拆开，粘贴的块插在中间。
- 3h 剪切后撤销：原样恢复（同一个 id）。

修掉的问题：选区的 slice 带着外层节点（outline > block > 段落），块内复制一开始被序列化成了大纲项；改为逐层剥掉两端都开着的外层节点。

没做：从网页 / Word 粘贴 HTML（原型总是优先用 `text/plain` 的 markdown）。

### 4 撤销 —— 通过

- 4a 在「最后一块」末尾：输入「一二」→ Enter → Tab → 输入「三四」。四次撤销后服务端状态依次等于第 3、2、1、0 步记录的状态；四次重做依次等于第 1–4 步；撤销后光标回到每一步之前的位置；Bob 与服务端一致。
- 4b 与 Bob 交错：Alice 在 P1b3 末尾输入 AAA，Bob 在开头输入 BBB，Alice 回车并输入 DDD，Bob 再输入 CCC。Alice 撤销三步：只去掉 AAA、拆块、DDD，Bob 的 BBBCCC 不动；Bob 撤销两步回到原文；Alice 重做三步，她的修改回来，Bob 撤掉的不回来。
- 4c 网络延迟 80 ms、对方的修改还在路上时撤销：只撤自己的，三方一致。
- 4d 在嵌入（P2 的块）里输入，再在 P1 里输入，撤销两次：两页都回到原状（同一个栈）。

### 5 并发 —— 通过

- 5a 两人网络都暂停，同时在同一块的同一位置和不同位置输入：放开后每个人的字都在且各一次，两个编辑器、两个客户端副本、服务端收敛。
- 5b Bob 在 P1b3 里打字，Alice 同时用 Alt+↑ 把它移到前面：块移动了，Bob 的字在块里，Bob 的光标还在同一个块的同一位置，继续打字落在光标处。
- 5c Alice 用 Tab 缩进 Bob 正在打字的块：同上。
- 5d Alice 把代码块拖到表格下面、Bob 同时把表格拖到代码块下面：服务端拒绝后到的那个（成环），Bob 丢弃本页本地状态重同步，三方收敛。
- 5e agent 读取 P1 之后 Alice、Bob 继续改，agent 一次写 5 处：
  - 在 Alice 修改过的块末尾追加：不重叠，合并；实时出现在 Alice 编辑器里，Alice 光标不动。
  - 改写 Bob 刚插入文字的那一段：重叠，拒绝，返回的当前内容里有 Bob 的修改。
  - 移动 Alice 读取之后移动过的块：版本不符，拒绝。
  - 新建一个写成「总结 + 列表」的块：拆成 1 个块 + 2 个子块，返回里说明「列表拆成子块」，实时出现在 Bob 编辑器里。
  - 改一个没人打开过的块（表格）：服务端先初始化 Y.Text 再写，所有人看到。
- 5f 正在编辑的块被对方删除：不崩、收敛；设计要求的「已被删除」提示和一键恢复**没做**。
- 5g 随机压力：两人随机打字 / 拆块 / 合并 / 缩进 / 减少缩进 / 移动 / 撤销 / 重做，网络随机暂停，agent 穿插写入。3 个种子 × 300 次操作，每次结束后两个编辑器、两个客户端、服务端全部一致；共 23 次事务被拒（都是「对方同时删了这个块」），被拒方重同步。

测出并修掉的问题：

1. **首次编辑窗口丢字。** 已有块的 Y.Text 由服务端在第一次被编辑时初始化；初始化到达之前的按键，原型作为带基线的 text 操作发给服务端三方合并。按 §6.5 的严格规则，两个人在同一位置的并发插入算重叠 → 整个事务被拒 → 按键丢失（5a 里 Bob 的「乙」）。另外 Y.Text 到达时客户端立刻改用 Y.Text 的内容（还不含自己在途的修改），光标跳动、字序错乱（「远B）（端」）。改为：人的这类修改宽松合并（不拒绝，同位置插入排在后面）；被确认之前客户端一直显示乐观内容，后续输入继续走 text 操作。
2. **被拒绝后没有真正重置。** 重同步时没有重建这一页的 Y.Doc，被拒事务里的本地修改留在客户端，和服务端发散（随机压力测出）。

### 6 嵌入 —— 通过

- Alice 的 P1 里有两个嵌入子视图（P2b3、P1b3）。
- 6a 在嵌入（P2 的块）里打字：服务端 P2、Bob 看 P2 的编辑器、Bob 的 P1 里同一个嵌入都实时变化；选区留在嵌入里。
- 6b Bob 在 P2 里改：Alice 的嵌入实时变化。
- 6c P1b3 在 P1 里原位一次、经 `![[P1/P1b3]]` 嵌入一次，还在拼接视图里出现：Alice 网络暂停时在原位打字，嵌入那一处立即同步（同一客户端内传播，不经服务端）；在嵌入里打字，原位和拼接视图同步；Bob 的两处都同步。
- 6d Alice 在嵌入那一处、Bob 在原位同时改：四处一致。
- 6e 在嵌入的根上回车：新块成为被嵌入块的第一个子块（留在嵌入里），写进 P2。
- 6f 在嵌入里撤销：新块撤掉。
- 6g 让一个块的子块嵌入它自己：显示「循环嵌入」占位，不无限展开（整个页面四个编辑视图里共 12 个嵌入）。

### 7 性能 —— 通过（无头 Chromium 的相对数字）

页面：一个客户端、一页 2000 个块（三层嵌套，含标题、粗体、行内代码、提及），全部展开。「按键到画完」= keydown（捕获阶段）到这一帧画完（rAF 之后的 MessageChannel 回调），包含等下一帧（16.7 ms 节拍）；「本地处理」= 我们的 dispatch（reconcile + 序列化 + 写 Y.Text + 发事务）。共跑 6 次，给出范围：

| 指标（2000 块） | 结果 |
|---|---|
| 首次渲染（建文档 + 建视图 + DOM） | 68–118 ms（5000 块：167–447 ms） |
| 打字：按键到画完 | p50 13.7–19.1 ms，p95 22.7–28.5 ms，最大 25.8–94.7 ms（一次 94.7 ms 离群，疑似 GC） |
| 打字：本地处理 | p50 1.0–1.4 ms，p95 1.7–2.7 ms |
| Enter：按键到画完 / 本地处理 | p50 21.5–29.4 / 8.8–12.5 ms，p95 35.7–58.5 / 15.2–42.2 ms |
| Tab / Shift-Tab：本地处理 | p50 8.4–12.2 ms，p95 10.9–18.8 ms |
| 块首 Backspace 合并：本地处理 | p50 4.3–9.7 ms |
| 远端修改（agent 写一块）→ 出现在 DOM | p50 10.6–17.7 ms，p95 16.9–41.7 ms；每次投影 1.8–2.6 ms |
| 别人每秒改 20 次时打字：按键到画完 | p50 11.4–14.2 ms，p95 20.6–26.2 ms，最大 22–65 ms |
| 滚动（45,587 px，每帧 300 px，149 帧） | 帧间隔 p50 16.7 ms，p95 17.6–18.2 ms；超过 50 ms 的帧 0–1 个 |
| 内存 | JS 堆 9.1 MB（空页 2.7 MB）→ 约 3.3 KB/块；DOM 18,155 个节点（约 9 个/块）；一轮操作后 11.3–11.4 MB；5000 块 17.6 MB / 45,298 节点 |
| 500 块对照 | 打字本地处理 p50 0.7–0.9 ms；Enter 本地处理 p50 3.0–3.8 ms；每次远端投影 0.85–1.13 ms |
| Y.Text：首次编辑才建（设计） vs 会话开始全建 | 一轮测试后 P1 只有约 95 个 Y.Text、状态约 9 KB；全建 2,010 块：9–14 ms，编码 213 KB（正文 157 KB），堆 +0.8 MB |

说明：服务端和客户端在同一个线程里，服务端处理事务和 Y 更新的时间算在主线程上（但不在「本地处理」里）。结构操作和远端投影的耗时与块数成正比（见「对设计的影响」7）。没做超过 2000 块时的占位节点。

### 8 拼接视图 —— 通过

- 拼接视图的根是 P1b3、P2b1（任务）、P3b1。在三个根里分别打字：服务端各自的页变了，Bob 看 P1、P2 的编辑器同步，任务属性保留。
- 没有子块的根末尾回车：新块成为它在本页的下一个兄弟，在拼接视图里紧跟其后，Bob 的 P1 里出现。有子块的根末尾回车：新块成为第一个子块。
- 根上按 Tab 不生效（会跨页移动）；根的子块 Shift-Tab：在本页成为根的兄弟，并作为新的根出现在拼接视图。
- agent 改 P3 的块：拼接视图实时变化。
- 跨页的跨块剪切（从 P2 的块选到 P3 的块）：ProseMirror 默认把两端合并，等于把 P3 的块和子块挂到 P2 下面，违反「块不跨页」。服务端本来就会拒绝；原型改为本地直接拒绝（数据不变、没有往返和重同步）。同一页内的跨块剪切和撤销正常。
- 修掉的问题：拼接视图的根序列在本地校验之前就被改了，拒绝之后残留，导致下一次操作被误判为跨页。

## 对设计的影响

### §6.7 被证实的做法

1. **一个 ProseMirror 视图承载整个编辑面**（块节点带 id）：跨块选择、复制剪切粘贴、上下方向键、输入法都不用切焦点；Enter / Backspace / Tab / Alt+↑↓ 都能写成普通的 ProseMirror 事务。「每块一个编辑器」方案的缝隙在这里都不存在。
2. **块模型是真相、编辑器文档是投影**：按块建节点 + 未变节点按身份复用 + 只替换变了的范围，2000 块时一次远端修改的投影约 2 ms。同一个块出现在多处（原位、嵌入、拼接视图）保持同步是这个结构的自然结果。
3. **输入 → 大纲事务**：打字走快路径（本地处理 p50 约 1 ms）；结构操作 reconcile 成 insert / move / delete / task + 正文差异可行。
4. **远端修改按块重新解析 + 「源码偏移 ↔ 编辑器位置」映射**：对方在光标前插字、把段落改成标题并插入粗体和提及、移动或缩进正在编辑的块，光标都留在原处。
5. **本地正在组合的块推迟应用远端修改**：组合不被打断，块 DOM 不被替换，拼音不广播，提交后合并正确；其他块照常实时更新。
6. **块外框用原生 DOM 的 node view**：2000 块 18k DOM 节点、9 MB 堆，没有每块一个 React 根。
7. **嵌入用子编辑视图**：选区不跨边界，编辑直接写目标页。
8. **按页 Y.Doc + 每块 Y.Text 存 markdown 源；结构由服务端排序、移动后写为准、成环拒绝**：随机并发压力全部收敛。
9. **每个用户一个撤销栈**：每页一个 Y.UndoManager（只跟踪本地来源）加统一的步骤栈，交错时只撤自己的，跨页同一个栈。
10. **agent 按读取快照三方合并**：结果作为参与者写进 Y.Doc 实时出现，正在编辑的人光标不动。

### 要改的

1. **§6.7「与 Y.Text 当前内容做 diff」要改成「与 shadow 做 diff 再 rebase」。** 只要有还没投影进编辑器的远端修改（输入法推迟期间一定有），拿序列化结果和当前 Y.Text 做 diff 就会把它们覆盖掉——原型里实际丢过。正确做法：和编辑器上次反映的源码做 diff，再按期间的远端 delta 映射到当前文本上写。
2. **§6.3「已有块第一次被编辑时由服务端初始化」留下了窗口。** 初始化到达之前的按键：按 §6.5 的严格三方合并会把同位置并发输入判成冲突、丢字。原型改成宽松合并 + 确认前显示乐观内容，能用，但多了一套 text 操作、宽松合并和撤销时的三方回退。**建议 P1 改为页实时会话开始时就给这一页所有块建 Y.Text**：2000 块约 10 ms、213 KB、+0.8 MB，窗口消失，这一整支可以删掉。「没人同时编辑的块不经过 CRDT」对 agent 写入仍然成立（页不在实时会话时 agent 直接写 `content`）。
3. **块内方言（D23）要补一条：中文标点与强调的冲突。** CommonMark 的左右侧规则使「粗体 / 斜体以全角标点结尾、后面紧跟汉字」解析不出来：`这是**重点：**内容`、`**「重点」**内容`，12 种常见全角标点 12/12 失败；开头同理。中文里非常常见，所见即所得里用户加粗一段带标点的文字就会遇到。原型的做法：序列化后立即读回核对，把边缘的标点挪到标记外面（`这是**重点**：内容`，视觉几乎不变），实在不行去掉这段标记，保证文字不丢；随机中英混排段落里 29.6% 至少有一处要这样降级。D23 需要把这条降级规则定下来，并在三个解析器上确认。
4. **GFM 裸链接会把紧跟的 `[[…]]` 吞进网址**（marked 和 remark-gfm 都这样）。原型的方言不认裸链接（网址就是文字），但只读渲染（`MarkdownContent` + remark-gfm）仍会自动链接，两边不一致。要么只读渲染也关掉裸链接，要么序列化时保证网址和 `[[` 之间有空格。
5. **块合并会让被并入的块的 id 消失**，指向它的 `[[…]]` 会断。原型只做到「一边是空块时删空块、保住有内容的块的 id」。P1 需要在合并时把指向旧块的链接改指向合并后的块（或给旧 id 留重定向），并记进提交。
6. **拼接视图（以及任何跨页编辑面）需要按页拆开的删除。** ProseMirror 默认的跨块删除把两端合并，跨页时等于把后一页的块挂到前一页下。原型本地拒绝；P1 要写：两端各自截断、不合并，中间的块按页删除。
7. **全量 reconcile / 全树投影的代价与块数成正比**：结构操作 2000 块 9–12 ms（500 块 3–4 ms），每次远端投影约 2 ms。2000 块上限内可以接受；如果要多视图、更大页或低端设备，结构键位应直接产出大纲操作（命令知道自己做了什么），投影只重建脏块。
8. **「被拒绝时丢弃这一页的本地状态并重新同步」会连带丢掉被拒事务之后的本地修改。** 随机压力里 900 次操作被拒 23 次，都是对方同时删了块。真实使用里少见，但用户会看到刚打的字消失。P1：只回滚被拒的那个事务，其余待确认事务在新状态上重放；或服务端对「目标块已删除」做变换而不是拒绝。

### P1 要特别注意

- **真实输入法和移动端**：CDP 模拟没有候选窗、没有系统级事件。1i 已经显示，不经输入法的 Enter 会让 ProseMirror 在组合中拆块、留下「僵尸组合」——安卓键盘的 Enter 正是这类路径。macOS / Windows 的拼音、五笔、搜狗，iOS / Android 软键盘，Safari 都要真机测（第 2 项）。
- **shadow 和待投影 delta 的簿记是正确性的关键**：这次两个丢字 / 错位的 bug 都出在这里（对 Y.Text 而不是 shadow 做 diff；残留的「重置」标记）。P1 要给这部分单独写单元测试和随机测试，最好把「编辑器反映的版本」做成显式的状态。
- **推迟的粒度**：原型冻结的是组合中的块的整棵子树；如果这个块被别人移动或删除，整个视图的投影推迟到组合结束。长时间组合期间别人的结构修改会攒着。
- **撤销栈与 Y.UndoManager 对齐**：每步开始时对所有页的 UndoManager 调 `stopCapturing`，按栈长变化记下这一步涉及哪些页；撤销 / 重做时逐页调用。逆操作碰到对方已改结构（父块被删）时原型直接跳过并记日志，P1 要定用户看到什么。
- **方言的读回核对**每次按键多一次 marked 解析（已包含在约 1 ms 的本地处理里），长块（16 KiB 上限）要测；表格单元格里「代码里的反斜杠紧跟竖线」无法表示（降级去掉标记）。
- **设计里有、原型没做的**：50 ms 合并广播与背压、`outline_live_updates` 落库与崩溃恢复、会话空闲关闭与定稿、只看不编辑的页订阅（节流快照）、权限与踢出、「已被删除」提示与一键恢复、Esc 块选择模式、拖拽柄、超过 2000 块时的占位节点、从网页 / Word 粘贴 HTML、三个解析器的一致性模糊测试。服务端是同线程的内存对象，没有真实的 WebSocket 和序列化开销。

### 做了什么

- **编辑面**（`src/client/surface.ts`）：一个编辑面两种视图，共用一份视图状态（`viewstate.ts`：聚焦、折叠集合、光标块和块选择、视口锚点、导图方向）。折叠是视图状态，不进块模型、不产生提交；原型里存在内存里（一个编辑面一份），没有按（用户，页）存到服务端。
- **大纲视图**一直在：导图的结构键在它的文档上执行同一套 ProseMirror 命令（`commands.ts`；新增「加子块」「加到页尾」「拖到某块前 / 后 / 下」「删块」，原有的 Shift-Tab、Alt+↑↓、Mod-Enter 直接复用），经同一个 reconcile 变成大纲事务、进同一个撤销栈。所以和大纲里做同样的事结果一致是构造上保证的，测试是在核对这一点。
- **导图视图**（`src/mindmap/`）：
  - 布局：van der Ploeg 2014 的非分层紧凑树（线性时间，节点大小不一），向右 / 向下两种只是交换坐标轴；单元测试：随机树（30 个种子 × 两种方向）不重叠、同级有序、父块居中，2 万块 < 200 ms。
  - 尺寸：pretext 测量，按标记拆成富文本片段（粗体、斜体、行内代码、提及各用自己的字体和外边距），代码最多 6 行不换行，表格固定宽度最多 6 行。预测的节点高度和 DOM 最大差 0.5 px。测量按正文缓存，另有按块的尺寸缓存，布局时只有变了的块要重测；树布局每次整棵重算（2000 块 p95 ~1 ms）。
  - 渲染：原生 DOM 节点绝对定位在一个平移缩放的容器里，只给视口附近（±320 px）的节点建 DOM；连线是一层 SVG 里的一条 path。最小版平移缩放（滚轮、拖动、Ctrl+滚轮、双指）。
  - 节点外框和大纲共用（`chrome.ts`：折叠箭头、项目符号、复选框），块体用同一份 schema 的 toDOM。
  - 编辑：节点里放一个只编辑这一块的 OutlineView（新的 surface kind `node`：只有这一块的块体，不带子块），同一份 schema、方言、输入法推迟、源码映射；Enter 拆块后编辑跟到新块。
- **切换动画**：记下切换前可见块的屏幕位置，算出目标布局，FLIP（WAAPI，250 ms，和 `vlist-motion-scheduler` 的 LOD 切换同一个时长）；锚点块（离视口中心最近的块，上次的锚点还在视口里就沿用）在屏幕上不动；只给切换前或切换后在视口里的块做位移动画，其余淡入淡出。导图 → 大纲时导图节点移动到大纲行的位置，结束时换成大纲。
- **聚焦**：整页一个大纲视图，聚焦时另建一个以聚焦块为根的视图，整页视图停放（`content-visibility: hidden`）；导图里聚焦就是以这个块为根重新布局，被聚焦的块移到根的位置。地址栏 `#/outline/<页>/<块>`（原型没有路由，用 hash），`history.state` 里记两个编辑面的聚焦。
- **快速切换**（`switcher.ts`）：内存索引（标题 = 第一行纯文字，别名 = `alias::` / `别名::` 属性行，正文 = 全文小写），子串匹配，最近访问加权。
- **Worker 预先测量**（`measure-worker.ts`）：页面打开后把整页块体发给 Worker 用 OffscreenCanvas 测，结果和主线程一样（同一份代码、同一套系统字体）。

帧时间是一路试出来的（同样 13 次切换，p95 / 最长帧）：

| 做法 | p95 | 最长 | 说明 |
|---|---|---|---|
| 第一版：隐藏的大纲 `opacity: 0` + `pointer-events: none` | — | 58 ms 的样式重算 | `pointer-events` 是继承属性，改它要重算整棵大纲（2 万元素）的样式 |
| 去掉 `pointer-events`，导图里给大纲加 `content-visibility: hidden` | — | 每帧 +20 ms | 大纲里残留的 DOM 选区：浏览器每帧算选区边界，被跳过排版的子树要往后扫整页（`UpdateSelectionBounds` → `nextCandidateAlgorithm`）。导图拿焦点时清掉选区 |
| 上一条 + 清选区 + 先读后写 | 20.2–21.9 ms | 40–52 ms | 回大纲那一帧解锁整页要重做 PrePaint + Paint（~23 ms） |
| 不锁大纲（只透明） | 23.7–26 ms | 36–59 ms | 导图里每次改动隐藏的大纲也要重画；节点里打字 p95 41–57 ms |
| 切换分两帧（先算 / 建看不见的 DOM，下一帧再显示、起动画） | 19.1–20.8 ms | 44–48 ms | 解锁的 23 ms 还在 |
| **最终**：两帧 + 隐藏的大纲平移到编辑区外面（排版一直有效，绘制被视口裁掉）+ 来回切换不重复布局 / 不重复派发光标 | 18.1–20.9 ms | 29–48 ms（一次 112 ms 离群） | 剩下的长帧是每次切换的头一两帧（建 ~40 个节点的 DOM、大纲重新显示） |

计划里的两条退路：「只给视口里的块做动画」本来就是这样做的（每次 14–34 个节点动画）；「降低导图的可见块上限」对帧时间没用（只给视口附近的节点建 DOM，导图 DOM 一直是 30–60 个节点，长帧来自大纲那一侧）。没有改动画时长（250 ms；放到规格允许的 300 ms 会让 p95 更好看，但那是稀释，不是变快）。

**2 状态带过去。** 默认页 Alice。状态一：P1b4 缩进到 P1b3 下并折叠 P1b3，点项目符号聚焦 P1b2，在 P1b2_2 里选中 3–6；状态二：整页、向下布局、Esc 块选择 P1b3（用工具栏按钮切换）；状态三：在导图里空格折叠 P1b2、Shift 点选 P1b9、选中 P1b6，带回大纲。每组 20 次来回，前 10 次等动画结束、后 10 次在动画中途切回；每次切回大纲都核对整份视图状态，导图里核对根、选中、块选择的高亮。

**3 导图编辑。** 同一套语义步骤在两个全新页面里各做一遍：一个只用导图（选中 P1b3 → Tab 打字 → Esc → Enter 进入编辑 → Enter 加同级打字 → Esc → Shift-Tab → Alt+↓ → 空格折叠 P1b2 → Mod-Enter → 把 P1b9 拖到 P1b5 中间 → 把 P1b1 拖到 P1b5 靠后的四分之一），一个只用大纲键位（光标在末尾 Enter + Tab、Enter、Shift-Tab、Alt+↓、点折叠箭头、Mod-Enter、Alt+↑ ×3 + Tab、Alt+↓ ×5），每一步之后比对服务端的块树（不带 id）：8 步全部一致。撤销：大纲打字 → 导图 Tab → 节点里打字 → 导图 Alt+↓ → 大纲 Enter → 大纲打字 → 导图 Mod-Enter，在导图里撤销 3 步、大纲里撤销 4 步、大纲里重做 3 步、导图里重做 4 步，每一步和记录的块树一致。并发：Alice 在节点里打字时 Bob 在大纲里往同一块前面插字并把它下移；Alice 网络暂停时 Tab 加子块、Bob 同时缩进这一块；Bob 删掉 Alice 正在编辑的块（编辑器退出，不报错）。

**4 节点里的输入法。** 和 P0 第 1 项同样用 CDP 的 `Input.imeSetComposition` / `insertText` 模拟。另外核对了：组合中 Enter / ↓（keyCode 229）不拆块；提交后真 Enter 拆块，编辑跟到新块。

**5 聚焦。** 见结论。动画中途的连续操作：大纲里 Alt+→ → 打「壹」→ 点「导图」→ Alt+← → 点「向下」→ → → Alt+↓（聚焦）→ 点「大纲」→ 打「贰」→ Alt+→ → Alt+← → 点「向右」，中间不等。

**6 快速切换。** 「按键到聚焦完成」= Enter 的 keydown 到聚焦之后那一帧画完。聚焦进一个块不拆整页的 DOM（见「对设计的影响」4），所以 2000 块的页聚焦进去 4–12 ms；最慢的一次是从整页跳到另一页的块（建那一页的聚焦视图）。

**7、8** 见结论。触屏用的是 `Input.dispatchTouchEvent`（`hasTouch` 的上下文），浏览器自己合成 pointer 事件；没有真机。

### 和设计、计划不一样的地方

1. **Enter**：设计里同时写了「选中节点后……按 Enter 进入编辑」和「Enter 加下一个同级」。原型：选中节点时 Enter 进入编辑（光标在末尾）；编辑中的 Enter 就是大纲的拆块（同一条 `splitBlock`，在末尾就是加下一个同级，编辑跟到新块）。连续录入是「Tab、打字、Enter、打字、Enter……」，和大纲一样。要「选中就加同级」得先 Enter 再 Enter。**需要负责人定。**
2. **Alt+方向键**：设计里「Alt+方向键移动块」和「Alt+→ 聚焦、Alt+← 退一层，两种视图一样」在导图里冲突。原型：同级方向上的 Alt+方向键移动块（向右布局 Alt+↑↓，向下布局 Alt+←→）；层级方向上的 Alt+方向键聚焦 / 退出（向右布局 Alt+→ / Alt+←，和大纲完全一样；向下布局转了 90° 是 Alt+↓ / Alt+↑）。导图里没有「缩进」键（Tab 是加子块），挂到别的块下面用拖动。**需要负责人定。**
3. **项目符号点了聚焦，折叠改由左边的折叠箭头负责**（设计 §6.10「点项目符号聚焦」）；P0 是点项目符号折叠，第 0 项测试的选择器跟着改了。
4. **编辑区改成固定高度的滚动容器**（导图要和大纲叠在同一个视口里），P0 第 7 项的滚动测量改为滚编辑区。
5. **字体**：页面字体从 `system-ui` 改成具名字体栈（Inter、PingFang SC、Noto Sans CJK SC、文泉驿……）。pretext 要求具名字体（`system-ui` 在 macOS 上测不准），大纲和导图同一套字号字体，切换时文字不重新换行。
6. 平移缩放是原型自己写的最小版，没用 `PanZoomStage`（计划允许）。
7. 布局只有「测量」是增量的；树布局每次整棵重算（线性时间，2000 块 ~1 ms）。van der Ploeg 算法里父节点的分离会改写子树的线程和修正量，按子树缓存要额外的复位逻辑，量下来没必要。
8. 折叠和方向没有按（用户，页）持久化；地址栏是 hash（原型没有路由）。

### 没测的

- Safari、iOS、Android、真实输入法、真实触屏、有 GPU 的桌面 Chrome（帧时间是无头软件渲染的相对值）。
- 选中节点后直接用输入法打字（键盘事件 229 时进入编辑、让组合落进节点的编辑器）：实现了，没测；验收第 4 项是先 Enter 进入编辑再组合。
- 鼠标双击进入编辑（和触屏连点共用一段逻辑，只测了触屏）；Ctrl+滚轮缩放；拖动时的落点提示。
- 块选择模式下的批量操作（导图里 Shift 点选的一组只是状态，结构键只作用于当前节点）。
- 超过 2000 块时的「…还有 N 项」节点、缩小到很小时的简化渲染（LOD）。
- 在场：导图节点上的对方标记画了（和大纲同一个样式），没专门测。

### 对设计的影响

1. **pretext 的冷测量不便宜：每块 0.2–0.3 ms。** 2000 块当场测 400–540 ms，导图首次画出 465–623 ms，远超 200 ms。pretext 在 Worker 里能跑（OffscreenCanvas），结果和主线程一致；页面打开后在 Worker 里预先测完（~0.5 s，不占主线程），首次画出就是 42–60 ms。P1 要把「打开页就在 Worker 里测」做成默认，用户在 Worker 测完之前切到导图时还是会卡一下（剩下的块当场测）。预测精度很好：节点高度和 DOM 最大差 0.5 px（具名字体 + 按标记拆片段）。
2. **两个视图叠在同一个视口里时，隐藏的那个怎么藏决定了帧时间。** 不要切换继承属性（`pointer-events` 一改就是整棵子树的样式重算，2000 块 58 ms）；不要在被跳过排版的子树里留 DOM 选区（每帧 ~20 ms）；`content-visibility: hidden` 省了导图里的开销，但切回来解锁那一帧要对整页重做 PrePaint + Paint（~23 ms）；把隐藏的大纲平移到视口外（排版一直有效、绘制被裁掉）最好。这些都写进了 `style.css` / `surface.ts` 的注释，产品照做。
3. **切换要分两帧做**：第一帧只读位置、算布局、建看不见的 DOM（键盘焦点立即交给目标视图），下一帧再显示、起动画；新的切换或输入到来时先把第二步做掉。单帧的活儿少一半，用户感知只晚一帧。即便这样，每次切换的第一帧仍是 20–47 ms，p95 ≤ 20 ms 在无头软件渲染下是贴着线过的（10 次运行 8 次过）；真机有 GPU 应当宽裕，但 P1 要在真机上复测，必要时考虑在大纲每个顶层块上用 `content-visibility: auto`（让大纲的绘制只和可见块数有关，没做：会改变大纲的滚动高度估算，要单独评估）。
4. **聚焦不要在同一个编辑器里换文档。** P0 的做法（同一个 ProseMirror 视图里把整页替换成子树）从 2000 块的页聚焦进去要 88–115 ms（拆 2000 个块的 DOM），退出要 170–210 ms + 一次整页排版。原型改成整页视图一直留着（聚焦时停放），聚焦另建一个以聚焦块为根的视图：聚焦进去 4–12 ms，退出 ~5 ms + 一帧重绘（~50 ms）。产品的编辑页（`/outline/$spaceId/$blockId`）应当在路由层面保留整页的编辑器实例，而不是随 `blockId` 重建。
5. **导图的结构键直接在编辑面的大纲文档上执行同一批 ProseMirror 命令**，节点编辑器是 surface kind `node` 的 OutlineView：reconcile、撤销、并发、输入法都没改一行就能用。§6.7「同一个编辑面还有导图视图」可以按这个结构落地；代价是导图模式下大纲视图也在内存里（2000 块 ~10 MB 堆、2 万 DOM 节点）。
6. **锚点要「粘住」**：每次都取离视口中心最近的块，来回切换几次后锚点会换块、视口慢慢漂。原型的规则是「上次的锚点块还在视口里就沿用」，20 次来回偏差 ≤ 1 px。导图回大纲只能对齐纵向（大纲不横向滚动）；因为锚点粘住，来回切换时横向也是 0 px。
7. **P0 遗留问题：首次编辑窗口里的输入，重做会把字序弄反。** 光标刚进入一个还没有 Y.Text 的块就打字：第一个字走 text 操作（服务端初始化 Y.Text 之后三方合并），后面的字走 Y.Text，两者合在同一个撤销步骤里；撤销正确，重做后变成「二一」。确定性复现：暂停网络 → 进块打「一」→ 恢复 → 打「二」→ 撤销 → 重做。P0 代码上同样复现，PR1 的全量运行里第 4 项因此失败过一次（时序碰巧落进窗口）。这进一步支持 P0 结论里「§6.3 改为页实时会话开始时就给所有块建 Y.Text」——那样这条路径整个消失。原型没修。
8. **设计里的键位冲突要定**：Enter（进入编辑 vs 加同级）、Alt+→（聚焦 vs 移动块），见上一节。
